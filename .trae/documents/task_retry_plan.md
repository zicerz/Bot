# 任务失败重试机制实现方案

## 需求分析

用户要求实现：任务失败后经过10分钟重试，最多重试三次。

根据配置文件中的说明和用户反馈：
- 每次刷新失败重试时都发送通知
- 只在第三次重试失败后发送通知
- 并在10分钟后再次开始此任务，并发送通知
- 时间可配置
- 注意区分文件级的任务和webhook级的任务
- 重试时间与已配置任务时间冲突时，等待已配置任务执行后再执行重试
- 重试配置设置为全局设置

## 代码结构分析

当前代码已有的重试机制：
1. **Excel启动重试**（3次，指数退避）- 在ExcelProcessor的`__enter__`方法中
2. **截图重试**（3次）- 在`capture_screenshots`方法中
3. **文件上传重试**（3次）- 在`_upload_file`方法中
4. **企业微信发送重试**（3次）- 在`_send_wechat`方法中

但缺少**任务级别**的重试机制，即整个任务失败后，等待一段时间再重新执行整个任务。

## 实现方案

### 1. 新增全局配置项

在 `config.yml` 中新增全局重试配置：
```yaml
retry:
  enabled: true               # 是否启用任务级重试
  delay_minutes: 10           # 重试间隔时间（分钟），默认10分钟
  max_attempts: 3             # 最大重试次数，默认3次
```

### 2. 文件级任务与Webhook级任务的区分

- **文件级任务失败**：整个Excel文件处理失败（如Excel启动失败、数据刷新失败），需要重试整个任务
- **Webhook级任务失败**：特定webhook发送失败（如截图失败、消息发送失败），只影响该webhook，其他webhook继续执行

### 3. 修改任务执行逻辑

在 `ReportTask` 类中：
- 添加 `retry_count` 属性追踪重试次数
- 添加失败时发送通知的逻辑（仅第三次失败后发送）
- 区分文件级失败和webhook级失败的处理

### 4. 修改任务调度器

在 `TaskScheduler` 类中：
- 支持动态添加延迟重试任务
- 使用 schedule 库的调度机制
- 当重试时间与其他任务配置时间相同时，等待已配置任务执行后再执行重试

## 详细实现步骤

### 步骤1：在配置文件中添加全局重试配置

```yaml
retry:
  enabled: true               # 是否启用任务级重试
  delay_minutes: 10           # 重试间隔（分钟）
  max_attempts: 3             # 最大重试次数
```

### 步骤2：修改 ReportTask 类

1. 在 `__init__` 方法中加载全局重试配置
2. 添加重试计数器属性
3. 在执行失败时：
   - 文件级失败：记录失败并触发重试机制
   - webhook级失败：跳过该webhook，继续处理其他webhook
4. 仅在第三次重试失败后发送通知

### 步骤3：修改 TaskScheduler 类

1. 添加 `_schedule_retry` 方法，支持延迟调度
2. 修改 `_run_task` 方法，在任务失败时触发重试调度
3. 检查重试时间是否与其他已配置任务时间冲突
4. 如果冲突，将重试任务延迟到配置任务执行时间之后（+1分钟）再执行

## 预期行为

1. 任务执行失败时（文件级失败），记录失败状态
2. 检查重试时间是否与其他任务配置时间冲突
3. 如果冲突，将重试时间延迟到配置任务执行时间之后
4. 等待配置的重试间隔时间（默认10分钟）后执行重试
5. 重试过程中不发送通知
6. 达到最大重试次数（3次）后，发送最终失败通知

## 优先级规则

1. 配置任务（在times中配置的时间点）优先级最高
2. 重试任务优先级低于配置任务
3. 如果重试时间与配置任务时间冲突，将重试任务延迟到配置任务执行时间之后

## 风险评估

1. **并发问题**：多个重试任务可能同时执行，需确保文件锁机制正常工作
2. **内存占用**：重试任务会占用一定内存，但由于重试间隔较长，影响较小
3. **配置冲突**：需确保重试配置与其他配置不冲突
4. **时间冲突**：需正确处理重试时间与配置任务时间的冲突，确保重试任务在配置任务之后执行
